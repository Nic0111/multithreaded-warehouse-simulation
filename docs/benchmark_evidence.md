# Benchmark Evidence Guide

Use these files when writing the Results and Discussion section.

## JSON and CSV Evidence

- `output/bench/benchmark_bundle.json`: async-vs-threaded comparison, synchronization benchmark, and allocation proof.
- `output/bench/async_bench_summary.json`: async latency, drift, deadline, and leaderboard summary.
- `output/bench/threaded_bench_summary.json`: threaded latency, drift, deadline, and leaderboard summary.
- `output/demo/priority_summary.json`: priority scheduling proof; human p99 drift should be lower than bot p99 drift.
- `output/demo/fail_safe_summary.json`: fail-safe entry, bot drops, and recovery proof.
- `output/demo/watchdog_summary.json`: real 10 second watchdog reset evidence.
- `output/replay_async_500/async_summary.json`: async replay evidence from 500 captured live Wikimedia events.
- `output/replay_threaded_500/threaded_summary.json`: threaded replay evidence from the same 500 captured live Wikimedia events.

## Recommended Data Volumes

- Presentation demo: keep the controlled demo sizes generated by `cargo run -- demo`.
- Report benchmark: run `cargo run -- bench --output-dir output/bench --events 1000`.
- Live authenticity: run `cargo run -- capture --output data/replay/captured_recentchange.ndjson --limit 500`, then replay the same file through both architectures.

## Criterion Evidence

Run:

```powershell
cargo bench
```

Criterion writes the browsable report to:

```text
target/criterion/report/index.html
```

Use screenshots or tables from that report to support the zero-copy parsing and async-vs-threaded p99 latency discussion.
